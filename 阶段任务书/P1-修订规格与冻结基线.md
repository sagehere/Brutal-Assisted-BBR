# BABR-Lite 修订规格与冻结基线

版本：`p1-baseline-v3`；日期：2026-09-19；状态：**P1 FINAL CLOSED / G1 FINAL GO**。  
本文件替代原 [BABR v0.2 规格](../Brutal-Assisted%20BBR（BABR）拥塞控制算法设计规格.md) 以及 `p1-baseline-v1/v2` 中所有规范性公式、状态机和参数。v0.2、v1、v2 仅保留为设计与审计背景，不得作为实现依据。

**规范层级**：本文件定义行为语义；[P1-冻结参数与用例.json](P1-冻结参数与用例.json) 是其机器可读契约；[P1-恢复与IO事件桥接设计](P1-恢复与IO事件桥接设计.md) 只映射固定宿主接口；检查器只能验证前两者，不能自行创造或覆盖规则。若重复描述发生冲突，Final Closure 必须失败而不是选择性解释。

## 1. 范围、宿主与不变量

首发范围是 Cloudflare quiche 0.29.3 的 `Bbr2Gcongestion`，固定提交 `55886df3be579579207104c8e645825b6347a209`，用于单发送方向、持续供数、受控长连接 QUIC 实验。socket 成功遥测使用同一提交中的 tokio-quiche I/O worker 或具有等价成功回调的薄宿主。首版只定义 BABR-Lite：`Target` 不使用 `T/A` 补偿，候选探测速率由 Target、基线和预算共同限制。它不是生产算法，也不包含独立 CWND 增长、Adaptive Target、竞争流识别、多路径协同或聚合调度器。恢复与 I/O 事件桥接以 [P1-恢复与IO事件桥接设计](P1-恢复与IO事件桥接设计.md) 为本规格的强制附录。

所有速率使用 byte/s，窗口使用 byte，时间使用单调时钟的 ms。若宿主接口给出 bit/s，换算为 byte/s 后才参与计算。每个连接仅有一个发送方向 Target；同一拥塞控制实例内的应用流不得分别叠加 Target。

必须同时满足以下不变量：

1. 辅助禁用、`W=0`、保护阶段、在线关闭或输入无效时，最终 pacing、CWND 和 burst 许可精确采用同一外部策略下的基线输出。
2. 每轮辅助均受绝对截止时间、总发送字节预算和无收益退出约束；任何一个到期都停止辅助并进入失败退避。
3. 基线的 LossDetected、PTO、主动减速和 CWND 裁剪优先。固定 quiche 0.29.3 不向 BABR 提供可用的 persistent-congestion 或 ECN-CE 控制信号，因此两项能力为 `unsupported`，不得伪造。辅助从不扩大 CWND，也不覆盖 pacer 的最终发送许可。
4. 超大 Target 不会增加本轮冻结的参考速率、时间预算、字节预算或 10% 相对增幅上限。
5. 未知、过期、零分母、AppLimited、接收流控、策略限速和路径事件均不会成为继续加码的理由。

## 2. 配置与计量

权威参数在 [P1-冻结参数与用例.json](P1-冻结参数与用例.json)。Target 缺省或为零关闭辅助；非数、负数、介于零与 1,000,000 byte/s 之间的非零值，以及大于 125,000,000 byte/s 的值均拒绝配置并保留上一个有效配置。`MaxRate` 是可选的连接硬上限；设定后同时裁剪基线和辅助，且当 `MaxRate < Target` 时记录 `policy_limited` 并不进入辅助。

| 名称 | 定义 | 有效性与用途 |
| --- | --- | --- |
| `model_delivery_rate` | quiche BBRv2 网络模型在 ACK 批处理后的有效交付率 | 复用宿主采样器；可学习，不能因样本来自辅助而丢弃 |
| `unique_payload_goodput` | 接收端已交付的应用载荷字节区间除以测量窗口 | QUIC 按 `(stream_id, offset, length)` 去重；重传首次交付计一次，重复或迟到 ACK 不重复计数 |
| `receiver_app_throughput` | 接收应用实际消费的唯一载荷 | 与发送端 goodput 分开报告，不作为 Lite 实时控制输入 |
| `actual_sent_rate` | 成功提交给 socket 的全部 QUIC 包字节除以窗口 | 包含重传和协议开销；生成包或仅进入用户态队列不计为实际发送 |
| `A` | 已判定发送批次中唯一确认载荷/实际发送字节 | 仅为后续损失补偿遥测；Lite 不计算或使用 `T/A` |
| `η` | 有可识别探测批次时，反馈窗口内 delivery 增量/实际发送增量 | 分母低于 1,000,000 byte/s、反馈未齐、样本过期、正在降速时为无效；无效不是 1，也不能加码 |

执行预算与真实发送遥测使用两个独立计数器。`assist_budget_debit_bytes` 在 quiche 成功生成带辅助增量的单个 QUIC datagram 时按该 datagram 的 wire bytes **立即预扣且永不退款**；后续 socket 失败、WouldBlock 或部分写入都不恢复额度。`actual_socket_sent_bytes` 仅在 socket/GSO 成功返回时按实际 `n` 增加。安全预算与 actual-send telemetry 不得复用同一计数器。不可撤销卸载队列超调上限为 2,400 byte。

## 3. 有界辅助规则

一次辅助轮次从进入 `ASSIST` 时开始，冻结 `B_ref = model_delivery_rate`、`start_time`、`assist_deadline = start_time + 300ms` 与 `budget = B_ref × min(3 × MinRTT, 300ms)`。这是保守的总发送预算，不宣称等于相对基线的真实额外流量。`B_ref`、预算和失败历史不会因为新样本、Target、空闲、模式开关或短暂 RTT 抖动而提高或重置。Assist admission 粒度固定为**单个 QUIC datagram**：每个 datagram 在生成前独立检查额度，成功生成后按 wire bytes 预扣且 socket 失败不退款；GSO 只能聚合已经逐 datagram 获得 admission 的包。

只有 `ProbeBW.Refill`、`ProbeBW.Up` 和 `ProbeBW.Cruise` 可以请求辅助；`Startup`、`Drain`、`ProbeRTT`、`ProbeBW.Down`、任何已观测丢失事件、PTO、AppLimited、接收流控受限和策略受限均是禁止状态。相位必须来自 BBRv2 的明确状态字符串或内部枚举，不能由 `pacing_gain` 推测。冻结宿主的 `BBRv2::is_in_recovery()` 含未决 TODO，因此 BABR 不使用它；quiche 0.29.3 也不提供可供 BABR 使用的明确 persistent-congestion 或 ECN-CE 控制信号，二者能力固定为 `unsupported`，不得在 P1/P2 中伪造控制律。未来宿主若提供经验证信号，应仅作为更高优先级的撤销保护。

每个 BBR packet-timed round 最多执行一次辅助决策。开始时 `W=0`，每个可增益决策最多增加 `0.05`，范围为 `[0,1]`。软延迟只冻结 W，不增加它；紧急退出不等待 round。速率计算为：

```text
P_cap   = min(Target, 1.10 × B_ref)
P_final = B_ref + W × max(0, P_cap - B_ref)
P_final = min(P_final, MaxRate)     # MaxRate 存在时
CWND_final = CWND_bbr
```

实际输出仍经过 quiche 的现有 pacer、`can_send()`、路径发送许可及配置的 `max_pacing_rate`。`W=0` 显式返回 `P_bbr` 与 `CWND_bbr`，不保留辅助 burst 或窗口。

一轮在最早发生的条件下结束：已经 3 个 BBR round、`now >= assist_deadline`、已用执行预算达到冻结预算、无收益、Hard 条件或任一基线保护事件。时间源为 monotonic clock，规范单位 ms，检查分辨率 1ms；**新 Assist 字节的 deadline grace 固定为 0ms**。timer callback 晚到只能记录遥测，绝不能延长 Assist 许可。经过两个完整 round 后，若 `model_delivery_rate < 1.02 × B_ref`，无收益成立，独立于 RTT。每次预算耗尽、无收益、超时或 Hard 都增加失败编号 `n` 并进入 `ASSIST_BACKOFF`：

```text
backoff(n) = min(30s × 2^(n-1), 10min), n 从 1 开始
```

退避期间只运行基线；一次 delivery 上升、Target 变更、空闲重启、日志丢失、模式切换或单次 RTT 波动均不提前解除。经宿主确认的路径迁移立即取消本轮辅助并使输入失效，但连接级退避仍保留至原截止时间；新路径需先通过基线重新获得有效样本。

`queue_delay = SRTT - MinRTT`。当它大于等于 `max(10ms, 0.25×MinRTT)` 时为 Soft，冻结 W；当大于等于 `max(20ms, 0.5×MinRTT)` 时为 Hard，立即撤销辅助并退避。这是停用阈值，不是端到端排队时延保证。固定 quiche 0.29.3 当前没有可供 BABR 使用的已验证 ECN-CE 控制信号，因此本版本不产生 ECN reason code；未来宿主若提供该能力，只能通过新规格版本接入为撤销/冻结保护。

## 4. 权威状态机与事件顺序

状态为 `BASELINE`、`ASSIST`、`ASSIST_BACKOFF`。所有状态持续更新 quiche 的模型、丢失检测和恢复；BABR 从不维护影子基线。

| 优先级 | 当前状态 | 条件 | 原因码 | 动作 | 下一个状态 |
| ---: | --- | --- | --- | --- | --- |
| 1 | 任意 | Target 关闭 / 无效；mode 非 Lite；策略限制 | `TARGET_DISABLED / INVALID_TARGET / MODE_NOT_LITE / POLICY_LIMITED` | 清零 W，发布基线 | BASELINE |
| 2 | 任意 | 路径变化、AppLimited、ReceiverLimited、样本无效 | `PATH_CHANGED / APP_LIMITED / RECEIVER_LIMITED / SAMPLE_INVALID` | 清零 W；相应样本失效 | BASELINE |
| 3 | 任意 | LossDetected | `LOSS_DETECTED` | 清零 W；failure++；当前样本失效 | ASSIST_BACKOFF |
| 4 | 任意 | PtoFired | `PTO_FIRED` | 清零 W；failure++；当前样本失效 | ASSIST_BACKOFF |
| 5 | 任意 | 禁止 BBR 相位 | `BBR_PHASE_PROTECTED` | 清零 W，发布基线 | BASELINE |
| 6 | 任意 | Hard queue guard | `HARD_QUEUE_DELAY` | 清零 W；failure++ | ASSIST_BACKOFF |
| 7 | ASSIST | `now >= assist_deadline` | `ASSIST_TIMEOUT` | 清零 W；failure++ | ASSIST_BACKOFF |
| 8 | ASSIST | 执行预算不足以 admission 下一 datagram | `ASSIST_BUDGET_EXHAUSTED` | 清零 W；failure++ | ASSIST_BACKOFF |
| 9 | ASSIST | 已达 3 BBR rounds | `MAX_ROUNDS` | 清零 W；failure++ | ASSIST_BACKOFF |
| 10 | ASSIST | 两完整 round 后模型收益 <2% | `NO_BENEFIT` | 清零 W；failure++ | ASSIST_BACKOFF |
| 11 | ASSIST | `D >= 0.9T` | `TARGET_NEAR` | 清零 W，发布基线 | BASELINE |
| 12 | ASSIST | Soft | `SOFT_FREEZE` | 保持 W，重新裁剪 | ASSIST |
| 13 | BASELINE/ASSIST | 其余有效 packet-timed round | `BOUNDED_PROBE` | 每 round W 至多 +0.05 | ASSIST |
| - | ASSIST_BACKOFF | 当前时间小于退避截止 | `BACKOFF_ACTIVE` | 发布基线，不增加失败 | ASSIST_BACKOFF |

发送入口在**每个单独 QUIC datagram**生成前再次检查 mode、`now < assist_deadline`、剩余预算是否足以覆盖该 datagram 以及不可撤销队列字节数；任一检查失败都丢弃辅助增量并让基线决定是否可发。datagram 成功生成即预扣执行预算，socket 失败不退款。定时器晚到不影响发送入口的硬截止，因此 ACK 停止或 OS 调度迟到都不会延长辅助。任何事件处理中的输出发布必须一次性包含 BABR 状态、W、pacing、CWND 和已登记 reason code。

## 5. 配置、遥测和实验契约

Target 上调不改变正在执行的探测；Target 下调立即重算候选，基线可以继续高于 Target。在线 `off` 或 `observe` 在下一发送决策前清零 W；`observe` 记录候选但输出必须与 off 完全一致。多个连接只允许在受控实验中使用固定连接数，阶段 03 必须报告逐流吞吐、总 goodput、Jain 指数和相对匹配双基线的竞争流退化。

每次状态转换与每次辅助决策记录单调时间、连接/路径标识、配置版本、BBR 状态、BABR 状态、round、Target、B_ref、基线/候选/最终 pacing、CWND、inflight、实际发送率、model delivery、unique goodput、RTT、A/η 有效性、预算、失败数、退避截止与原因码。环形缓冲最多 4,096 条，序列化日志最多 1 MiB/分钟；P1 的预设开销门槛为 p95 CPU 增量不超过 2%、每连接内存不超过 256 KiB。

主要验证场景固定为 `500→100→500 Mbps`、Target `200 Mbps`；主要候选收益为达到 `0.9T` 的时间降低至少 20%。次要场景是 500 Mbps、Target 200 Mbps、1% 和 5% 随机丢包。关键场景至少 10 次独立运行；正常无损场景 goodput 退化不超过 3%，发送成本增幅不超过 10%，总 goodput 未提高时竞争流吞吐下降不超过 10%。


## 6. Reason Code 与参数来源

权威 reason-code 枚举及其 `clear_w / increment_failure / enter_backoff / invalidate_sample` 属性由 `P1-冻结参数与用例.json` 定义；实现不得产生未登记原因码。参数性质与来源见 [P1-冻结参数来源表](P1-冻结参数来源表.md)，其中 `EXPERIMENTAL` 值是首版冻结实验参数，不代表理论常数。
