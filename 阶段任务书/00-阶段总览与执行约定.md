## 2. 所有阶段共同遵守的约定

- 技术负责人维护规则和实现；验证负责人复现关键证据，可由同一工程师承担，但必须按干净环境复现流程核查。项目负责人依据阶段记录决定后续投入；此处为角色定义，不预设具体人员。
- 每项任务使用本文件组中的任务编号追踪，状态为未开始、进行中、完成或受阻。完成必须附代码/文档位置、版本与验证证据，不能仅标记“已实现”。
- 每个阶段交付一份阶段验收记录：任务完成情况、复现命令、输入配置、代码提交、原始结果位置、未解决问题和 Go/No-Go 结论。若暂未建立 Git 仓库，先记录宿主提交和本地补丁哈希。
- 工程产物放入宿主已有文档、测试和实验目录；没有惯例时再建立最少目录。任务书中的交付物名称表示内容要求，不强制一项一个文件。
- 参数在实验前固定；修改参数、代码或主要评价场景后，标记新实验版本。探索数据与最终验证数据分开，不可选择性删除失败结果。
- 任何阶段发现预算绕过、禁止阶段辅助发包、错误计量或恢复破坏，先修复并重跑受影响检查；吞吐收益不能抵消安全失败。
- 既有基线的有效交付样本继续学习；禁止把无效效率样本设为 1，也禁止为了追逐 Target 绕过基线安全裁剪。
- 不默认开展生产发布、公网推广、内核移植、Adaptive Target、Confidence Model、多路径协同或新的聚合调度器。这些不属于当前四阶段的交付范围。

## 4. 后续投入规则

G1、G2 通过只表示技术与安全条件满足，不代表已证明收益。G3 通过才支持投入损失补偿；G3 不通过时可基于明确失败原因进行一次有范围的修正并重验，不能无期限调参。G4 无增量收益时保留 Lite 是正常结果。即使四阶段均通过，也只形成受控试验候选，生产化需另立任务书。
