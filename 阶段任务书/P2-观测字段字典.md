# P2 Observe 观测字段字典

版本：p2-observe-v1 / p2-lite-v2
依据：`p1-baseline-v4`  
适用范围：阶段 02 Observe。**这些字段用于测量与解释，不得直接改变 pacing、CWND、send permission 或 recovery。**

## 1. 结构化记录

每条记录采用 newline-delimited JSON；schema 固定为 `p2-observe-v1`。

| 字段 | 类型/单位 | 来源 | 语义 |
| --- | --- | --- | --- |
| `schema` | string | telemetry | 固定 `p2-observe-v1` |
| `seq` | u64 | telemetry ring | 单调记录序号 |
| `t_us` | μs | monotonic `Instant` | 从本次 Observe telemetry 启用后的首条记录起算 |
| `phase` | string | BBRv2 explicit Mode/CyclePhase | 不通过 pacing gain 推断 |
| `reason` | string | Observe output | Observe 固定为 `MODE_NOT_LITE`，表示候选未施加到传输输出 |
| `shadow_reason` | string | 冻结状态/guard 规则 | 解释如果评估候选时当前最重要的原因 |
| `baseline_pacing_Bps` | byte/s | BBRv2 | 原始 BBR baseline pacing |
| `baseline_cwnd_bytes` | byte | BBRv2 | 原始 BBR CWND；内部紧凑记录使用 u32，溢出时饱和并置 flag |
| `model_delivery_Bps` | byte/s | BBRv2 network model | 模型交付率；不是 unique payload goodput |
| `unique_payload_bytes` | byte/null | Connection STREAM range ledger | 唯一确认 STREAM payload；重传/迟到重复 ACK 不重复计数 |
| `actual_socket_sent_bytes` | byte/null | tokio-quiche socket/GSO `Ok(n)` | 只累计真实成功返回字节；Err/WouldBlock 不计 |
| `flags` | u16 bitset | telemetry | 记录有效性、可用性与同采样点多 guard 事件位 |

## 2. flags

当前 bit 定义：

- bit 0：`END_OF_ROUND`
- bit 1：`SAMPLE_VALID`
- bit 2：`APP_LIMITED`
- bit 3：`LOSS_DETECTED`
- bit 4：`CWND_SATURATED`
- bit 5：`UNIQUE_PAYLOAD_AVAILABLE`
- bit 6：`SOCKET_SENT_AVAILABLE`
- bit 7：`EVENT_PATH_CHANGED`
- bit 8：`EVENT_APP_LIMITED`
- bit 9：`EVENT_RECEIVER_LIMITED`
- bit 10：`EVENT_POLICY_LIMITED`
- bit 11：`EVENT_LOSS`
- bit 12：`EVENT_PTO`

未实现或不可验证的指标必须保持 unavailable；序列化为 `null`，不能用 0、虚拟候选速率或推导值代替。

## 3. reason code

reason code 完全沿用 `P1-冻结参数与用例.json` 的冻结词汇：

`TARGET_DISABLED`、`INVALID_TARGET`、`MODE_NOT_LITE`、`PATH_CHANGED`、`APP_LIMITED`、`RECEIVER_LIMITED`、`POLICY_LIMITED`、`BBR_PHASE_PROTECTED`、`LOSS_DETECTED`、`PTO_FIRED`、`BACKOFF_ACTIVE`、`SAMPLE_INVALID`、`TARGET_NEAR`、`ASSIST_TIMEOUT`、`ASSIST_BUDGET_EXHAUSTED`、`MAX_ROUNDS`、`HARD_QUEUE_DELAY`、`NO_BENEFIT`、`SOFT_FREEZE`、`BOUNDED_PROBE`。

Observe 当前实际输出的 `reason` 为 `MODE_NOT_LITE`；`shadow_reason` 可使用已经具备真实输入的保护原因和 `BOUNDED_PROBE`。尚未存在真实输入的 controller-only 原因不得伪造。

## 3.1 Lite 控制轨迹

Lite 的 schema 固定为 `p2-lite-v2`。它记录 `configuration_version`、单调 `seq/t_us`、phase/state/reason、`W_steps`、rounds、Target、B_ref、基线/候选/最终 pacing、CWND、model delivery、预算、预算预扣、不可撤销队列、失败数、deadline/backoff 剩余时间、`control_applied` 与 `dropped_records`。

`check_lite_trace.py` 对每条记录校验冻结 reason、序号/时间、预算、2,400 B 队列和保护阶段。它要求实际 Assist 记录同时拥有未过期 deadline；未知字段必须以 JSON `null` 保留，不能用零伪造。当前 host 尚未为每一条 Lite 记录暴露路径身份、inflight、RTT、样本年龄及 admission-to-socket 对应关系；L05/L06/L08/L09/L10 依赖这些字段的结论必须为 `BLOCKED`，直到真实宿主接线完成。

## 3.2 Lite v2 evidence fields

`p2-lite-v2` records are accepted only when every record has the following
fields. `connection_tag` is an FNV-1a tag of the source connection ID, so the
raw connection ID is never exported. `path_id` identifies the active host
path. `inflight_bytes`, `srtt_us`, `min_rtt_us`, `sample_valid`, and
`sample_age_rounds` are direct host snapshots at the decision point.

`assist_deadline_monotonic_us` is the authorization deadline in the same
per-trace monotonic epoch as `t_us`; `assist_deadline_remaining_us` remains a
diagnostic snapshot. Nullable fields use JSON `null`: no unavailable value is
replaced with zero. The host intentionally exports `null` for unidentifiable
metrics such as eta, additional delivery, and causal response; the checker
does not derive them from candidate pacing.

For a passing real Assist case, the checker requires a budget pre-debit and a
strict increase in the cumulative `actual_socket_sent_bytes` snapshot after
the first admission. `control_applied=true` alone is never treated as send
proof. Missing identity, sample, deadline, or socket-boundary evidence fails
the trace; an otherwise valid run with no real Assist remains `BLOCKED`.

## 4. 记录时钟与去 ACK 频率耦合

正常记录仅在以下条件之一成立时进入 ring：

1. BBRv2 `end_of_round_trip=true`；
2. 自上一记录后出现新的安全/限制 guard event。

因此高 ACK 频率本身不会提高记录频率，也不会成为 W 或 telemetry 的控制时钟。

## 5. 有界 ring 与日志预算

冻结约束：

- ring：最多 **4096 entries / connection**
- serialized output：最多 **1,048,576 bytes / 60 s**
- memory budget：最多 **262,144 bytes / connection**
- CPU p95 overhead budget：**≤2%**

实现规则：

- ring 满时丢弃最旧记录，并单调累计 `dropped_records`；
- 序列化额度按实际 JSON line bytes + newline 计费；
- 当前 60 秒窗口额度不足时停止 drain，未输出记录保留到下一窗口；
- telemetry 默认关闭；关闭状态不得为每 ACK 构造记录或分配 ring entry；
- Connection API 在启用一个真实 path 的 telemetry 前会关闭并释放其他 path 的 ring，确保冻结的 4096 条限制按 **connection** 而不是按 path 解释；
- 禁用 telemetry 会释放 VecDeque heap capacity，避免迁移后的旧 path 留存第二份 ring；
- 当前紧凑记录结构保持 ≤56 B；4096-entry payload 与 telemetry 状态结构静态合计低于 256 KiB。

CPU p95 ≤2% 仍须通过后续真实 off/observe 对照测试证明，单元测试不能替代该证据。

## 6. 数据源边界

- `LOSS_DETECTED`：只来自真实 recovery loss detection。
- `PTO_FIRED`：只来自真正 `pto_count += 1` 的 PTO 分支。
- `PATH_CHANGED`：只来自 PathMap 的真实 path identity / active path 切换。
- `actual_socket_sent_bytes`：只来自 socket/GSO `Ok(n)`。
- `unique_payload_bytes`：只来自被 ACK 的 STREAM `(stream_id, offset range)` 去重。
- Persistent Congestion、ECN CE：冻结宿主当前为 unsupported，不生成虚假字段或 reason。

## 7. 当前验收边界

该字段字典和实现已通过 P2 Observe Gate run `35429171561`，可证明结构、冻结词汇、同采样点多 guard 可见性、connection 级 ring 容量、静态 ring 内存预算与 serialized byte cap；仍不能替代：

- 宿主级 off == observe 输出对照；
- CPU p95、实际连接内存、真实日志速率测量；
- netns/tc/netem/tbf 受控网络轨迹；
- M2 Observe Gate 最终验收。
