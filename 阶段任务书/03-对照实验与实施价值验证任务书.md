# 阶段 03：对照实验与实施价值验证任务书

版本：1.0；日期：2026-09-18；状态：未开始；预计投入：2–4 人周。  
依据：[评估报告 R2](../BABR规格审核与实施评估报告.md) §5–6；前置：[阶段 02](02-观测模式与BABR-Lite原型任务书.md) G2 通过；共同约定见 [阶段总览](00-阶段总览与执行约定.md)。

## 1. 目标与范围

在安全约束不放松的前提下，判断 BABR-Lite 相比选定基线是否有可复现增量价值。核心对照为同宿主原版 BBR 与 Lite；off/observe 用于开销检查。Brutal、其他 BBR 版本可作为补充参考，但不能替代同实现对照。

本阶段不提前开发损失补偿，不以单次最佳结果、只看 TAR 或挤占其他流吞吐作为成功证据。

## 2. 开发与实验任务

| 编号 | 工作内容 | 完成证据 |
| --- | --- | --- |
| S3-01 | 固化实验配置、主要收益场景、停止规则、样本量、运行时长和分析方法 | 实验清单版本，注明探索集与验证集、预设阈值 |
| S3-02 | 复用现有实验工具搭建最小受控拓扑，校准容量、RTT、丢包、队列和机器性能 | 拓扑/脚本、环境清单、原版 BBR 对账与瓶颈校准结果 |
| S3-03 | 按矩阵分层执行单流、动态、反馈异常、配置、路径及竞争测试 | 每次运行配置、种子、退出码、原始时序和安全检查结果 |
| S3-04 | 生成统一指标，分析配对差异、置信区间、异常与成本；做独立复现 | 分析脚本、图表/汇总、逐流数据、失败和未达标样本列表 |

## 3. 实验配置要求

先覆盖 R2 的代表性组合，再围绕失败边界加密，不强求所有维度的完整笛卡尔积。每个配置记录容量、基础 RTT、Target、队列容量、丢包机制及其位置、流数、启动顺序、运行时间、MTU、卸载、pacer 配置、CPU/系统版本及算法提交。

初始种子集对关键场景至少 10 次独立运行；成对对照尽可能使用相同配置与随机种子，随机化算法运行顺序，说明不同发送轨迹下相同种子不保证逐包同损失。运行时长覆盖 Startup、进入、退出、完整冷却/抑制周期；具体时长在 S3-01 中确定。

预设主要收益场景优先取持续供数、随机丢包或容量恢复。报告稳态与瞬态结果，单独报告 Startup，不能把启动差异混成长期收益。容量 C 应注明是瓶颈服务速率还是实测唯一载荷速率。

## 4. 必测矩阵

| 组别 | 场景 | 重点 |
| --- | --- | --- |
| A | 静态高容量：500M/200M Target；0/1/5% 随机丢包；毫秒级与数百毫秒级 RTT | 收益、时钟敏感性、正常场景退化 |
| B | 150M/200M Target；policer 与 shaper 分开；低排队与深队列 | 目标不可达退出、有限成本、重复失败抑制 |
| C | 500→100→500M，阶跃及渐变 | 降容过冲、恢复时间、辅助与基线交接 |
| D | 浅/深 FIFO、AQM、按流调度；宿主支持的 ECN | 不同队列及显式信号下的安全性 |
| E | ACK 压缩/延迟、重排、突发丢包、反向拥塞、无 ACK | 误判、采样有效性和到期执行 |
| F | 应用供给不足、接收流控、本机 CPU/pacer 受限、空闲重启 | 非网络瓶颈不错误辅助 |
| G | Lite/BBR、Lite/CUBIC、Lite/Lite；不同 RTT、Target、流数和先后启动 | 逐流公平性、聚合注入与总 goodput |
| H | Target 动态升降/关闭/反复变更、硬限速、路径迁移及 RTT 抖动 | 配置和路径规则，不绕过预算 |
| I | 短流、高 ACK 频率、日志开关、运行中关闭辅助 | 资源开销、退出能力及短流代价 |

G 组的公平性参照必须成对匹配：例如 Lite+CUBIC 对照 BBR+CUBIC；Lite+BBR 对照 BBR+BBR。保持其他条件相同，不能拿不同流数组合直接比较份额。

## 5. 统计与验收指标

以实验前固定的阈值为准；以下沿用 R2 的初始工程门槛，任何调整必须在验证集运行前记录理由。

| 指标 | 初始验收要求 |
| --- | --- |
| 主要收益 | 预先指定场景中稳态唯一载荷 goodput 提高 ≥10%，或容量恢复后达到 0.9T 的时间降低 ≥20%，且差异超出运行噪声 |
| 无损正常场景 | goodput 退化不超过 3% |
| 延迟 | p95 RTT 相对基线增量不超过 max(5ms, 10%×基线 p95 RTT)；同时报告 p50/p99 和队列代理值 |
| 流量成本 | 每交付一个唯一载荷字节的实际发送字节成本增幅不超过 10% |
| 公平性 | 总 goodput 未提高时，竞争流相对匹配对照的吞吐损失不超过 10%；不得用均值掩盖饥饿 |
| 失败处理 | 所有不可达、无 ACK 等用例在冻结预算与容差内停用辅助，抑制规则有效 |
| 一致性与开销 | 保护阶段遵从基线；无 NaN、溢出和预算绕过；CPU/内存/日志符合阶段 01 门槛 |

主要效应报告重复运行的中心值、分布和 95% 置信区间；区间跨过零收益或成本边界时标记证据不足，按预设规则增加样本或停止，不能只报告点估计。统计方法在 S3-01 冻结，可用运行级配对差异分析，不将高度相关的逐 ACK 样本伪装成独立重复。

TAR 同时报告有足够供数的有效时间口径和整体业务时间，明确不可达目标。Time To Target 未达到时保留超时/删失记录和成功比例；不能仅平均成功样本。发送成本明确是否含协议开销，并保持各组一致。

在线 η 是观测信号，AGE/额外收益依赖配对实验。除同运行时间比较外，在冻结的总发送预算下补充 delivered bytes 与完成时间对照，防止把“多发”当作更高效率。报告逐流 goodput、总 goodput 和 Jain 指数，不单靠公平指数通过验收。

## 6. 交付物与 G3 出口

交付：可复现实验脚本/配置、环境清单、全部原始数据、分析程序、结果报告及失败归因。提供从干净环境到代表性结果的操作步骤，不要求使用特定仿真框架。

G3 决策：

- **继续阶段 04：**安全全部通过，至少一个预先指定场景达到收益门槛且正常场景/成本/公平性达标，同时存在值得验证损失补偿的场景。
- **保留 Lite：**Lite 价值成立，但没有必要增加损失补偿，或增量问题不在损失补偿范围。
- **修正后重验：**有明确、有限的实现或测量缺陷；记录修正范围及受影响用例，验证数据重新生成。
- **停止：**收益不足、仅来自不公平份额转移、成熟基线修正已足够，或安全约束下无法产生价值。

本阶段通过不代表可以默认公网部署；输出是限定场景的实验结论。
