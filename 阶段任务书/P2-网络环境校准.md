## 1. 拓扑

```text
sender namespace            router namespace             receiver namespace
10.203.0.2/24 ---- veth ---- 10.203.0.1/24
                                      |
                               IPv4 forwarding
                                      |
                         10.204.0.1/24 ---- veth ---- 10.204.0.2/24
```

默认校准参数：

- bottleneck：100 Mbit/s；
- 单向传播延迟：20 ms；
- 正向随机丢包：0%；
- sender egress：`netem`；
- router → receiver egress：`tbf`；
- receiver egress：反向 `netem`。

`netem` 与 `tbf` 放在不同 egress 点，避免依赖 classless qdisc 嵌套行为，同时确保两者均真实位于端到端路径。

## 2. 自动入口

```bash
sudo -E bash tools/p2/netns/calibrate.sh
```

CI：`.github/workflows/p2-network-calibration.yml`。

该校准必须真实执行以下能力：

1. 创建三个 `ip netns`；
2. 创建并迁移两对 veth；
3. router namespace 开启 IPv4 forwarding；
4. sender → receiver 未整形时可连通；
5. sender/receiver egress 可安装 `netem`；
6. router receiver-facing egress 可安装 `tbf`；
7. `tc -s qdisc` 能观察到预期 qdisc；
8. ping RTT 反映配置的双向传播延迟；
9. iperf3 receiver throughput 反映 TBF bottleneck；
10. 原始环境、qdisc、route、ping、iperf JSON 与 summary 均作为 artifact 保存。

## 3. 默认验收窗口

对 20 ms + 20 ms 的双向传播延迟：

- RTT 允许窗口：`0.70 × 40 ms` 到 `2.0 × 40 ms + 5 ms`。

对 100 Mbit/s TBF：

- iperf3 使用 4 个并发 TCP 流饱和 TBF；receiver aggregate throughput 允许窗口：70–115 Mbit/s。单流 congestion-window/socket-buffer ramp 不作为 TBF 失效判据。

该窗口用于确认整形**真实生效**，不是阶段 03 性能结论。后续正式实验使用各场景自己的冻结参数与重复次数。
