### 2.3 冻结宿主 Observe 信号与 GuardEvent

已通过可重复 patch 在固定 quiche SHA 上接入只读 Observe 信号：

- `transport_lost_bytes`：由真实 loss 事件累计。
- `unique_payload_delivered_bytes`：连接级、按 `(stream_id, offset range)` 去重后的唯一 STREAM payload 累计量；重传和迟到原包 ACK 不重复计数。

### 2.6 Bounded structured Observe telemetry

`0005-babr-observe-telemetry.patch` 已完成 S2-06 的静态/宿主实现部分：

- 新增 `babr_telemetry.rs`，schema 为 `p2-observe-v1`。
- telemetry 默认关闭；启用后仅在 BBR packet-timed round 或新 guard event 时记录，不随 ACK 频率刷记录。
- `reason` 在 Observe 固定为 `MODE_NOT_LITE`，明确最终传输输出仍是 baseline；`shadow_reason` 使用冻结 reason vocabulary 解释候选/保护原因。
- 20 个 reason code 与 `p1-baseline-v4` 逐项完全一致；controller-only 原因在没有真实输入时不得伪造。
- 同一采样点的 Path/App/Receiver/Policy/Loss/PTO 多个 guard 通过 u16 flags 独立保留，避免单一 shadow reason 覆盖其他安全事件。
- ring 上限固定为 4096 entries；紧凑记录结构 ≤56 B。
- Connection API 同时只允许一个真实 path 持有 ring；切换/禁用时释放旧 path VecDeque capacity，避免把 per-connection 预算错误扩大为 per-path。

- unavailable 指标序列化为 `null`，不使用 0 或虚拟候选值代替。
- 新 telemetry 文件已纳入 P2 Gate 的 behavior-read-only diff 审计。

自动测试已实际执行并通过：

- ring hard bound / dropped count；
- compact record + 4096 entries 静态内存预算；
- 1 MiB/min serializer cap；
- 20 个 reason code exact vocabulary；
- default disabled；
- disable releases ring storage；
- enable uses current guard counters as baseline，不回放历史事件；
- guard event 不等待 round end；
- simultaneous guard events remain visible；
- unavailable metrics -> JSON `null`。

代码验收：P2 Observe Gate run `35429171561` 成功；对应 P1 Final Gate run `35429171556` 成功。

### 2.11 Unique-payload 账本去重内存收敛

静态审计发现 `0004-babr-unique-payload-dedup.patch` 原实现额外维护 `BTreeMap<stream_id, RangeSet>`，且 `RangeSet::new(usize::MAX)` 在上游会转换为可继续增长的 BTree 结构；同时该账本在 Off 下也执行，既存在额外历史状态，又会污染 Off/Observe 开销基线。

已在 commits `8d18bb48` / `109dc54a` 收敛：

- 删除 BABR 独立的 per-stream RangeSet 历史账本；
- 复用 quiche SendBuf 本来就维护的 ACK RangeSet，按 ACK 前后已确认唯一字节差计算增量；
- 累计量仅保留 connection 级 u64；
- 只有 Observe accounting 启用时才做额外唯一载荷计算；Off 不再承担该 shadow measurement 成本；
- 迟到重复 ACK 在 stream 已收集时由宿主原有 `None => continue` 路径自然忽略。

该变更的目标是同时保持 L06 去重语义、减少重复内存，并让资源 Gate 真正比较 Off 与 Observe 的增量成本。最终有效性以 patch-stack 编译、L06 回归和真实 Observe CI 为准。

### 2.13 Observe 资源 Gate 完整证据与测量方法收敛

head `47e32b17715e81bb8915df08bfd1f9257daed076` 的 P2 Observe Overhead Gate run `35439746514` 首次完整产出 CPU、memory diagnostic 与 Log60 三类证据：

- CPU median overhead：约 **0.48%**；
- CPU p95 overhead：约 **26.39%**，冻结预算 **2%**，FAIL；
- 独立进程 peak-RSS 差值 median：约 **24 KiB**；
- 独立进程 peak-RSS 差值 p95：约 **1.15 MiB**；
- throughput median ratio：约 **-0.05%**；

### 2.24 M3.3b3a 在线事件冻结 Assist envelope

本批将“输出回到基线”和“销毁本次 Assist envelope”严格拆开：

- 普通 baseline-only 事件只清 W 并发布基线，继续保留本轮冻结的 `B_ref`、Target 快照、300 ms deadline、执行预算、已用 debit 与 rounds；
- Target 上调对正在执行的 Assist 使用冻结 Target，不扩大当前候选；Target 下调取 `min(current_target, frozen_target)` 并立即按更低目标重算/撤销；
- baseline detour 后若仍在原 deadline 内且重新满足准入，只能以 W=0 恢复**同一** Assist envelope，不得重新冻结 B_ref、延长 deadline 或补充预算；
- 在线 Off/Observe/短暂 AppLimited 只撤回实际辅助输出和 W，不重置 frozen envelope 与 failure/backoff history；
- 经宿主确认的 PathChanged 是例外：立即取消旧路径 Assist envelope，使新路径必须先靠基线重新取得有效样本；connection-level failure history 保留；
- failure/backoff 仍销毁当前 Assist envelope，退避规则不变；
- 新回归覆盖 Target 上调不扩探测、Target 下调即时收缩、mode/短暂 idle 不补预算、不延长 deadline，以及路径迁移取消 envelope 但不清失败历史。

该批只修 controller 的冻结状态机。M3.3b3 下一层仍需把在线 Target/MaxRate 更新接到真实 GRecovery/Pacer：尤其 MaxRate 必须成为基线与 Lite 共用的宿主硬上限，且配置更新不得伪造一个新的 BBR round。

### 2.25 M3.3b3b1 在线 MaxRate 宿主 Pacer 硬上限
