## 2. 已落地内容

### 2.1 可执行冻结规则参考模型

`tools/p2/replay/babr_model.py` 将阶段 01 的冻结规则变为可执行参考模型。该模型：

- 读取 `P1-冻结参数与用例.json`，拒绝非 `p1-baseline-v3`。
- 明确区分 `off / observe / lite`。
- Observe 仅计算 shadow candidate，不改变最终 pacing/CWND。
- W 只由 BBR packet-timed round 推进；ACK 事件本身不推进 W。
- 直接按白名单处理 `ProbeBW.Refill / Up / Cruise`，保护 Startup、Drain、ProbeRTT、ProbeBW.Down。
- 实现 Target、MaxRate、样本有效性、Soft/Hard queue-delay 的第一版确定性判定。
- 任何模式切换都会清理 shadow W，防止 Observe 状态泄漏到 Off/Lite。

该模型不是网络实现、不是性能证据，也不能替代真实宿主集成。

### 2.3 冻结宿主 Observe 信号与 GuardEvent

已通过可重复 patch 在固定 quiche SHA 上接入只读 Observe 信号：

- `0001-babr-observe-signals.patch`：显式 BBRv2 phase、`end_of_round_trip`、baseline pacing/CWND、model delivery、sample validity/min RTT/max bandwidth、app-limited/loss 元数据。
- `0002-babr-transport-guard-accounting.patch`：记录真实 `LossDetected`、真实 PTO 分支的 `PtoFired`、`AppLimited`，并为 `PathChanged(path_id)`、ReceiverLimited、PolicyLimited 提供显式上层事件入口。
- Guard 使用单调计数而不是单个 last-event 槽，避免 Observe 快照之间覆盖安全事件。
- recovery 层不会从 RTT 变化推断路径迁移；PathChanged 必须由上层真实 path identity 注入。
- 未使用 `BBRv2::is_in_recovery()` 作为 BABR 安全信号。

Observe 计量字段当前严格区分：

- `model_delivery_rate_bytes_per_second`：BBRv2 模型交付率。
- `recovery_packet_bytes_sent`：recovery 层 packet bytes；**不是** socket-success。
- `transport_acked_bytes`：新确认的 transport packet bytes；**不是** unique-payload goodput。
- `transport_lost_bytes`：由真实 loss 事件累计。
- `unique_payload_delivered_bytes`：连接级、按 `(stream_id, offset range)` 去重后的唯一 STREAM payload 累计量；重传和迟到原包 ACK 不重复计数。
- `actual_socket_sent_bytes`：仅由 tokio-quiche `flush_buffer_to_socket()` 的成功 `Ok(n)` 累计；partial 仅计 `n`，Err/WouldBlock 不计。

最新代码验证：P2 Observe Gate run `35428248386` 成功；确定性 replay（含完整 L06 事件链）、`0001 → 0002 → 0003 → 0004` 顺序应用、patched quiche 测试、patched tokio-quiche(gcongestion) 测试、只读边界检查全部通过。对应 P1 Final Gate run `35428248387` 同样成功。

### 2.4 真实 Path identity 与 socket/GSO success 计量

`0003-babr-path-socket-accounting.patch` 已完成：

- 活动路径真正切换后，使用 PathMap 的真实 `path_id` 记录 `PathChanged(path_id)`。
- 不从 RTT 波动、loss 或 recovery 状态推断迁移。
- tokio-quiche `IoWorker::flush_buffer_to_socket()` 成为 `actual_socket_sent_bytes` 唯一事实边界。
- `Ok(n)` 只累计实际成功返回的 `n`；partial send 不按计划长度计数；Err/WouldBlock 不计。
- recovery packet bytes 与 actual socket bytes 始终保持不同指标语义。

### 2.5 L06 unique payload 去重核心

`0004-babr-unique-payload-dedup.patch` 已完成连接级 STREAM payload 去重：

- 使用每个 `stream_id` 的已确认 offset range 集合计算唯一 payload。
- 相同 range 的重传 ACK 或迟到原包 ACK 增量为 0。
- 部分重叠 range 只累计此前未确认的新字节。
- 不同 stream 的相同 offset 独立计数。
- tracker 位于 Connection 级，因此真实 path migration 不会清空 dedup 历史。
- zero-length FIN 不增加 payload。
- 当前该指标明确为 **unique STREAM payload**，不把 CRYPTO、QUIC header 或 packet ACK bytes 混入 goodput。

单元回归已覆盖：首次 [0,4) +4、重复 [0,4) +0、部分重叠 [2,6) +2、另一 stream [0,4) +4，总计 10。

此外已新增 `tools/p2/replay/traces/l06_retransmission_late_ack.json` 与确定性 accounting replay：

1. packet 100 socket-success 1250 B，STREAM [0,1200) 尚未交付；
2. packet 100 被标记 loss，不退款发送成本；
3. packet 101 重传同一 STREAM range，再计 1250 B 发送成本；
4. ACK packet 101，unique payload 首次增加 1200 B；
5. 原 packet 100 迟到 ACK，记录为 spurious ACK，但 unique payload 保持 1200 B。

最终对账：`actual_socket_sent_bytes = 2500`，`unique_payload_delivered_bytes = 1200`，`sent_packets = 2`，`loss_events = 1`，`ack_events = 2`，`spurious_ack_events = 1`。

因此 **L06 的确定性 recovery/accounting 事件回放已闭环**。这仍不是受控实网证据，不替代阶段 02 后续 network gate。

### 2.6 Bounded structured Observe telemetry

`0005-babr-observe-telemetry.patch` 已完成 S2-06 的静态/宿主实现部分：

- 新增 `babr_telemetry.rs`，schema 为 `p2-observe-v1`。
- telemetry 默认关闭；启用后仅在 BBR packet-timed round 或新 guard event 时记录，不随 ACK 频率刷记录。
- `reason` 在 Observe 固定为 `MODE_NOT_LITE`，明确最终传输输出仍是 baseline；`shadow_reason` 使用冻结 reason vocabulary 解释候选/保护原因。
- 20 个 reason code 与 `p1-baseline-v3` 逐项完全一致；controller-only 原因在没有真实输入时不得伪造。
- 同一采样点的 Path/App/Receiver/Policy/Loss/PTO 多个 guard 通过 u16 flags 独立保留，避免单一 shadow reason 覆盖其他安全事件。
- ring 上限固定为 4096 entries；紧凑记录结构 ≤56 B。
- Connection API 同时只允许一个真实 path 持有 ring；切换/禁用时释放旧 path VecDeque capacity，避免把 per-connection 预算错误扩大为 per-path。
- newline-delimited JSON 序列化按实际 line bytes + newline 计费，严格限制 1,048,576 B / 60 s；当前窗口额度不足时停止 drain，记录保留到下一窗口。
- unavailable 指标序列化为 `null`，不使用 0 或虚拟候选值代替。
- 新 telemetry 文件已纳入 P2 Gate 的 behavior-read-only diff 审计。

自动测试已实际执行并通过：

- ring hard bound / dropped count；
- compact record + 4096 entries 静态内存预算；
- 1 MiB/min serializer cap；
- 20 个 reason code exact vocabulary；
- default disabled；
- disable releases ring storage；
- enable uses current guard counters as baseline，不回放历史事件；
- guard event 不等待 round end；
- simultaneous guard events remain visible；
- unavailable metrics -> JSON `null`。

代码验收：P2 Observe Gate run `35429171561` 成功；对应 P1 Final Gate run `35429171556` 成功。

> 边界：上述结果证明 **ring/record/serializer 的静态有界性**，不等于 CPU p95 ≤2% 或整连接实际内存 ≤256 KiB 已完成实测。unique-payload range ledger 等其他 Observe 内存也必须计入后续真实 overhead gate。

1. `pacing_rate()`；
