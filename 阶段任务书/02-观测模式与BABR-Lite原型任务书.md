# 阶段 02：观测模式与 BABR-Lite 原型任务书

版本：1.1；日期：2026-09-19；状态：实施中（Observe；Lite 未解锁）；预计投入：1–2 人周。  
依据：[评估报告 R2](../BABR规格审核与实施评估报告.md) §3–4；前置：[阶段 01](01-规格收敛与基线冻结任务书.md) G1 通过；共同约定见 [阶段总览](00-阶段总览与执行约定.md)。

## 1. 目标与范围

实现默认不改变发送行为的观测模式，再在受控环境实现 BABR-Lite。证明辅助可计量、有界、可退出且不破坏基线；本阶段不宣称吞吐收益已经成立。

只使用阶段 01 锁定的宿主、基线、参数和状态表。Lite 的目标候选为 T，随后仍须通过辅助增长、预算与宿主安全约束。保持基线 CWND 处理，不引入 `T/A`、独立窗口扩大、Adaptive Target、多路径或新的竞争检测。

> 实施记录：2026-09-19 已建立 `p2-observe-lite`，开始 M0/M1；当前仅允许无发包影响的 Observe 参考模型与宿主接线工作。Observe Gate 通过前不得启用 Lite 实际辅助发送。详见 [P2 实施记录与验收](P2-实施记录与验收.md)。

## 3. 实施顺序与中间检查

先完成 S2-01/02 和 S2-06 的观测部分，确认计量与宿主无扰动，再实施 lite 发包。观测模式检查必须满足：

- 在相同输入事件序列及相同外部策略下，observe/off 的最终 pacing、CWND 和发送许可一致。
- 网络实测中观测开销符合阶段 01 的 CPU、内存、日志预算；无法满足时先减少日志和重复计算。
- η、AGE 和额外交付不从虚拟候选速率推导；观测轨迹不被描述为启用后的网络轨迹。
- 模型交付率与唯一载荷计量能够解释差异；重传首次交付与重复确认计数正确。

网络实测轨迹存在调度噪声，不要求两次独立网络运行逐包相同；精确一致性在确定性事件回放/逻辑检查中验证，实网关注有无控制介入和测量开销。

## 4. 必须保持的实现约束

辅助截止不能等待 ACK。定时器负责到期处理，发送入口再次检查；到期后不再发出具有辅助增量的新批次。对既有不可撤销队列按阶段 01 的容差核算，保留宿主 PTO 等合法恢复探测。

W=0、保护状态或在线关闭时，最终输出遵循同条件下的基线。原子发布状态与输出，避免先清 W、后续回调却继续使用旧速率。即使关闭辅助，也继续模型更新、恢复和实际发送事件处理。

有效 η 只在真实激励及对应反馈具备时产生；无收益退出按已冻结的观察规则执行。未知效率不能支持进一步增益，也不能延长时间或字节预算。Soft 至少禁止增加辅助，Hard 与预算到期优先于达到 Target 的判断。

Target 变化、短暂空闲、日志丢失和统计窗口重置均不得补充已用预算。真实路径迁移使用宿主路径身份处理；单次 RTT 抖动不重置失败历史。MaxRate 影响所有发包，策略受限单独记录。

## 5. 最小自动回归与受控发包用例

| 编号 | 输入/场景 | 验证点 |
| --- | --- | --- |
| L01 | observe、off、W=0 与收缩后的基线 CWND | 确定性输入下输出一致；无辅助窗口残留 |
| L02 | 超大 Target；W 爬升；同轮 BtlBw 增大 | 单轮上限与冻结预算不自我抬高 |
| L03 | 150M policer、200M Target，低 RTT 膨胀 | 在辅助预算内退出；抑制期不重新加码 |
| L04 | Drain、ProbeRTT、Startup、恢复事件 | 立即禁用辅助；基线仍能控制 inflight 消退 |
| L05 | ACK 消失、持续拥塞、计时器迟到 | 无新 ACK 仍到期；发送入口拒绝过期辅助；宿主恢复保留 |
| L06 | 首次发送丢失后重传成功，随后迟到原包 ACK | 唯一载荷计一次；发送开销计全部实际发送 |
| L07 | 小激励、负差分、未到反馈、过期 RTT、异常数字 | η/输入有效性正确；未知状态不加码；无除零与溢出 |
| L08 | Target 升降/关闭/反复修改、MaxRate<T | 预算与退避不被重置；策略受限不追逐目标 |
| L09 | 空闲重启、确认迁移、仅 RTT 抖动 | 遵从路径和样本规则，不误解除抑制 |
| L10 | 真实容量增长、辅助撤销、在线关闭 | 有效样本可学习；能回归基线且不把 Target 变为上限 |
| L11 | 高 ACK 频率、日志开启/关闭 | 不随 ACK 频率加快 W 爬升；日志有界、开销达标 |

先用最小逻辑/事件回放检查边界，再在受控链路验证 L03/L04/L05/L10 等实际发送行为。对无法复现的场景记录阻塞，不以 mock 通过替代实际链路证据。

## 6. 交付物与 G2 出口

交付：宿主最小代码变更、构建与运行说明、观测及 Lite 模式配置、自动回归入口、受控测试轨迹、资源开销数据和验收记录。

G2 通过条件：所有安全回归通过；无未解决 P0；所有阶段 03 所需 P1 计量与控制定义已落实；日志可解释每次进入与退出；辅助开关有效；观测及 Lite 开销符合预设预算。没有吞吐改善不导致此阶段安全验收失败，但需如实记录并交阶段 03 判断价值。

若宿主安全限制阻止产生额外有效发送，保留限制并记录原因，不扩大 CWND 或忽略损失响应来“做出收益”。
