原 WSL2/Windows 尝试保留为历史记录：WSL2 当时缺 Rust/Cargo/CMake 且自动安装需要交互式 sudo；Windows 构建被 `boring-sys` 的 CMake/VS generator 依赖阻断。P1 不再把某台交互式 WSL 机器作为唯一验收环境，而采用仓库内 `.github/workflows/p1-gate.yml` 的干净 Ubuntu 24.04 自动门禁。

权威验证入口：

```bash
bash "阶段任务书/verify_p1.sh"
```

门禁固定执行：

1. 校验 `third_party/quiche-0.29.3` HEAD 必须为 `55886df3be579579207104c8e645825b6347a209`；
2. 记录 Rust/Cargo/CMake/Clang/pkg-config/Python/Git 版本；
3. 执行 `python3 阶段任务书/check_p1_rules.py`；
4. 执行 `cargo test --manifest-path third_party/quiche-0.29.3/Cargo.toml -p quiche --lib --features gcongestion`；
5. 对冻结规格、配置、检查器和关键 quiche 源文件生成 SHA-256；
6. 上传 `阶段任务书/p1-artifacts` 作为 CI 证据。

P1 的构建结论只以该干净环境实际退出码为准。阶段 02 的 `ip netns`、`tc netem/tbf` 和 CAP_NET_ADMIN 校准仍属于 G2 前置，不伪装成 P1 性能证据。

## 已核查接口与阶段映射

| BABR 所需事件 | quiche 0.29.3 位置 | 阶段 02 最小接入要求 |
| --- | --- | --- |
| 包生成与 pacing | `Connection::send()`；`gcongestion/pacer.rs` | 在 socket 提交前加入发送入口预算检查；记录 `SendInfo` 的排程时间与实际 socket 成功 |
| 实际发送 | `Pacer::on_packet_sent()` → `Controller::on_packet_sent()` | 仅在 datagram 成功提交时记 `actual_sent_bytes`；不可撤销队列上限 2,400 byte |
| ACK、丢失、交付样本 | `Pacer::on_congestion_event()`；BBRv2 `on_congestion_event()` 与 `network_model` | 复用 `Acked`/`Lost` 事件和 BBRv2 sample，不创建第二套带宽估计 |
| BBR 模式 | `bbr2/mode.rs`；`ProbeBW` 的 Up/Down/Cruise/Refill | 暴露明确模式字符串或枚举给 BABR，绝不由 gain 反推 |
| CWND 与最终许可 | BBRv2 `get_congestion_window()`、`can_send()`；Pacer | Lite 保持该窗口与许可；BABR 只能请求有界 pacing，最终仍走基线裁剪 |
| 应用受限 | `Pacer::is_app_limited()` 与 sampler 标记 | 受限即停止辅助，继续基线计量 |
| 丢失与 PTO | `gcongestion/recovery.rs::on_ack_received()`、`on_loss_detection_timeout()`；`path.rs` | 任意 `lost_packets>0` 或真正 PTO 都撤销辅助；PTO 只在非 `loss_time` 分支、`pto_count` 增加时记录 |
| 迁移 | `Controller::on_connection_migration()` | 暴露已确认路径身份和迁移事件；取消本轮并保持连接级退避 |
| Persistent Congestion / ECN | 固定 quiche 0.29.3 无可供 BABR 使用的明确控制信号 | 能力固定为 `unsupported`；不合成新判定器。未来宿主若提供经验证事件，只允许作为 Hard 撤销保护 |

`BBRv2::is_in_recovery()` 目前仅返回 `last_quiescence_start.is_none()`，附近源码含 `TODO(vlad): is this true?`。P1 明确禁止 BABR 使用该返回值。阶段 02 按 [P1-恢复与IO事件桥接设计](P1-恢复与IO事件桥接设计.md) 从 recovery/loss-detection 层桥接明确的 LossDetected 与 PtoFired；任一事件立即撤销辅助并使该轮样本失效。

BBRv2 的 `on_retransmission_timeout()` 与 `on_connection_migration()` 当前为空实现；BABR 不依赖这些空回调。路径变化从 Path/Connection 层明确通知。固定版本没有明确 persistent-congestion/ECN-CE 控制信号，因此两项能力均记录为 unsupported，而不是由 BABR 自行发明替代判定。

发送计量也已经冻结：执行预算在 quiche 成功生成辅助 datagram 时保守预扣且不因 socket 失败退款；真实发送成本只在 socket/GSO 成功后按返回字节数记录。tokio-quiche `IoWorker::flush_buffer_to_socket()` 提供该成功边界。

已知风险包括：quiche 的 BBRv2 为实验性实现，且其 issue 追踪中存在空闲/低 CWND 平台相关问题。该类基线问题需要独立复现、归因和修复，不得作为 BABR 收益。
