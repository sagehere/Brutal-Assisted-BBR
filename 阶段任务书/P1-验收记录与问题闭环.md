## 剩余门禁与 G1 判定

P1 设计未决项已经闭环：

1. `BBRv2::is_in_recovery()` 明确禁止作为 BABR 安全输入；Loss/PTO 从 recovery/loss-detection 层桥接。
2. 固定宿主没有可用的 persistent-congestion/ECN-CE 控制信号，两项能力显式冻结为 unsupported，不创建替代控制律。
3. 执行预算使用 datagram 生成预扣且失败不退款；实际发送遥测使用 socket/GSO 成功返回字节，二者不混用。
4. 构建、规则检查、工具版本和 SHA-256 由 `P1 Gate` 在干净环境自动产出。

**唯一剩余门禁是首个 `P1 Gate` 的真实执行结果。**

- workflow 全部成功：G1 = Go，可进入阶段 02 的 observe 实现；实际 Assist 发包仍须遵守阶段 02 的“先 observe 后 Lite”门禁。
- workflow 失败：G1 = No-Go，按日志修复固定宿主构建或 P1 规则，不得绕过。

阶段 02 的网络命名空间、netem/tbf 校准和真实发包安全回归属于 G2，不再错误地作为 P1 完成条件。
